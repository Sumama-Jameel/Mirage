=== HOW THE ANTI-BOT BYPASS WORKS ===

Grok's web client runs obfuscated JS that generates a per-request
x-statsig-id. Requests without it get rejected with error code 7
"Request rejected by anti-bot rules".

Token layout (70 bytes, base64-encoded):
  header[49] + counter_le32[4] + sha256(method + "!" + path + "!" + counter + suffix)[0..16] + trailer[1]

Every byte is then XOR'd with a random key.

- header: 49-byte static fingerprint extracted once from the browser
- counter: seconds since epoch 1682924400 (May 1, 2023)
- suffix: static string baked into the challenge JS
- trailer: single constant byte

When the Statsig SDK evaluation fails (headless, first paint, etc.),
grok.com falls back to btoa("x1:" + error.toString()). The gateway
detects this pattern and logs it. The fallback token is NOT suitable
for persistent use — it changes per request and is rejected after
the SDK recovers.

=== NOTES ===

- The hash suffix changes rarely (grok.com deploy cycle).
- The header changes every page load (contains a random prefix byte)
  but is functionally equivalent (same verification blob).
- If grok.com returns 403 with "x1:" or "e:" prefix in the error,
  the Statsig SDK failed to load. Check browser console for errors.
- TLS fingerprint impersonation (wreq/BoringSSL) may be required to
  pass Cloudflare JA3/JA4 checks on grok.com.
